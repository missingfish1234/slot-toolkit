# SPINE 粒子系統（Particle Studio）v1.30.0

開發者：小魚骨頭

用瀏覽器離線編排 Spine 粒子特效，輸出 Spine 3.8／4.0／4.2 動畫與圖片；支援 In／Loop／Out 三段演出與既有骨架掛接。

- **開啟**：雙擊 `啟動粒子工作室.cmd`，或直接開啟 `dist/Particle-Studio.html`；不需要伺服器或網路。工作包管理器按「開啟」也是開啟後者。
- **操作**：先看 [使用指南](使用指南.md)（依工作流程撰寫，含快捷鍵與版本紀錄）；完整參數與轉換流程見 [使用說明.txt](使用說明.txt)。
- **轉換 `.spine` 工程**：需另裝對應版本的 Spine 編輯器，本工具不附帶。

## v1.30.0 重點

輸出的 Spine 關鍵幀大幅減少，畫面誤差維持在原品質容許範圍內：

- 粒子隱藏（出生前、死亡後）期間不再打 KEY，只用一個階梯 KEY 保持到下次出生。
- 位移、旋轉、縮放、顏色各自精簡：尺寸曲線的節點不再強迫位移軌也打 KEY，反之亦然。
- 整段沒有變化的軌道（例如不旋轉時的旋轉軌）只保留 1 個 KEY。
- 殘影拖尾的位移／旋轉／縮放／顏色改為精簡輸出（過去每幀都打 KEY），內建殘影範例由 11,788 個 KEY 減至 3,097 個。
- 「烘焙檢查」新增 **極簡** 品質：位移容許 1.5 px、旋轉 1.5°，適合快速、細小或加亮的特效，KEY 數依效果與曲線而定。

一般粒子範例的 KEY 數約減少 30–55%。舊專案重新開啟後按「更新烘焙」或「輸出 Spine」即可套用。

## v1.29.9 重點

輸出拉伸光帶時分別精簡網格變形與顏色關鍵幀，保留貼圖切換與原設定的階梯變化。隱藏頭部粒子時，Spine 只保留頭部插槽和素材。可在「烘焙檢查」查看精簡後的 KEY 數。

## v1.29.8 重點

修正歷史拖尾在曲線與連續貼圖並用時容易超過烘焙上限的問題。重新開啟原專案後按「更新烘焙」或「輸出 Spine」即可套用。

## v1.29.7 重點

一般 Spine ZIP、批次 ZIP 和掛接追加包都可以另存。工具準備好 ZIP 後會顯示檔名，在 Chrome／Edge 按 **「選擇儲存位置」**，即可指定資料夾與檔名。按 **「下載 ZIP」** 則依瀏覽器的下載設定儲存。

解壓縮後，用 Spine 匯入 `匯入Spine_專案名.json`，用粒子工作室開啟 `粒子編輯專案_專案名.particle.json`。

掛接既有骨架時，上方輸出按鈕與 Ctrl＋E 會產生追加包 ZIP。需要更新原工程時，在掛接面板按 **「寫回原工程」**，工具會依原骨架檔名更新 JSON。

## v1.29.6 重點

背景參考圖可轉 JPG：在畫布下方按 **「背景轉 JPG」**，選 PNG／JPG／WebP，調整 **「JPG 品質」** 與 **「透明區域底色」**，查看預覽後選 **「下載 JPG」** 或 **「套用為參考圖」**。轉換保留原解析度，例如 2440 × 1440 仍為 2440 × 1440，透明區域會填入選定底色。

來源支援 32 MiB、單邊 8192 px、16 Mi 像素；超過 4 MiB 時會逐步降低 JPG 品質，仍無法符合限制就明確提示，不會縮圖或改寫原始檔。一般「載入參考圖」遇到過大的檔案也會開啟轉換對話框。此功能只處理背景參考圖，粒子貼圖保持透明 PNG；背景圖僅供對照，不加入 Spine 輸出。

## v1.29.5 重點

修正反覆修改移動／收縮時間後，光帶越調越細的問題。預覽與輸出按移動／收縮時間保留足夠存活時間，原生命設定不被反覆改寫；把時間調大再改回，會恢復同一組設定對應的粗細與淡出表演。

舊專案若生命已被先前版本改大，而且仍需恢復原效果，可到 **「發射 → 數量與生命」** 把生命長度改回原值；也可重套 **「彗星撞擊」**，重設時間與曲線並保留貼圖及路徑。新版會沿用專案已存的生命值，無法自動判斷舊案原本的數值。

## v1.29.4 重點

移動與拖尾收縮可分開計時：在 **「運動 → 拖尾表演」** 啟用 **「獨立移動／收縮時間」**，分別設定 **「移動到達」** 與 **「收縮結束」**。按 **「彗星撞擊」** 可一次設成出生後 0.5 秒到達終點、0.65 秒收完尾巴；頭部到達後停住，尾巴繼續縮短。時間都從每顆粒子出生時計算，預覽與輸出會保留足夠存活時間，原生命設定保持，拉伸長度仍可超過 200%。

範例 `examples/path-comet-impact.particle.json` 內嵌自製藍光貼圖。光帶沿 S 曲線移動，0.5 秒抵達，0.65 秒頭尾消失。

## v1.29.3 重點

拉伸長度支援 **0–1000%**，可超過 200%。在長度曲線上選取節點，再於 **「拉伸長度」** 輸入 **250、500 或 1000**，圖表會自動調整縱軸。整條路徑鋪圖超過 100% 時，開放路徑沿終點方向延長，封閉路徑沿原路徑繼續繞行；寬度維持原設定。**「先長再短」** 預設仍保留原本的 15% → 100% → 5%。

## v1.29.2 重點

拉伸長度可隨時間變化：在 **「運動 → 拖尾表演」** 勾 **「啟用拉伸長度曲線」**，按 **「先長再短」** 就能讓光帶伸長後縮回，寬度保持原設定。曲線橫軸是每顆粒子出生後的生命進度，縱軸是長度比例；可拖節點調整，或改用貝茲與階梯表演。選 **「維持全長」** 可回到固定長度。

範例 `examples/path-ribbon-length.particle.json` 的光帶在 2 秒內由 15% 拉至 100%，再縮至 5%。可開啟 `examples/path-ribbon.particle.json` 比較固定全長的表演。

## v1.29.1 重點

整條路徑光帶：載入自己的 PNG 後，在「運動 → 拖尾表演」按 **「把目前貼圖做成路徑光帶」**，保留目前貼圖與原路徑，一次設成單一連續光帶；工具會自動切網格，不需要先手動製作 Mesh。效果庫也可直接加入 **「整條路徑光帶」**。

手動設定時，選 **「整條路徑鋪圖」**、取消 **「顯示頭部粒子」**、粒子數設 **1**；直向貼圖的 **「貼圖長邊」** 選 **「直向」**。完整貼圖會從路徑起點鋪到終點，寬度用粒子尺寸及寬度倍數調整，生命曲線控制整條光帶的出現與消失。**「跟隨移動拖尾」** 則保留沿已走過軌跡拉伸的表演。

範例 `examples/path-ribbon.particle.json` 內嵌自製的 48 × 112 直向藍光貼圖，單一粒子沿可編輯的 S 曲線鋪成光帶。動畫長 3 秒，開啟時停在 1.2 秒。

## v1.29 重點

路徑拖尾：效果庫新增「沿路徑拉伸」與「殘影拖尾」。在「運動 → 路徑與拖尾」編輯路徑，貼圖能沿彎曲的移動軌跡拉成網格，或留下逐漸淡出的多張殘影；可調殘留時間、殘影數、寬度倍數、拖尾透明度、尾端收尖與彎曲細緻度。粒子生命結束後，既有尾巴仍會逐漸消失。預覽與 Spine 3.8／4.0／4.2 烘焙輸出共用取樣，並可沿用骨架掛接與三段演出。

範例：`examples/path-trail-stretch.particle.json`、`examples/path-trail-afterimage.particle.json`，皆為 3 秒非循環動畫，圖片已內嵌。

## v1.28 重點

網格閃電：效果庫新增「網格閃電」圖層，用一張閃電貼圖沿長邊切成網格，每次變化重新扭曲成新的閃電，輸出為 Spine 網格變形（3.8／4.0／4.2 皆用官方 runtime 驗證）。可切換「兩端固定」與「尾端擺動」，支援多條同時出現、隨機分岔、粗細與亮度跳動、閃斷；畫布上拖藍色端點調整長度與方向。可搭配「點角色加效果」掛到既有骨架並寫回。

## v1.27 重點

強化既有 Spine 更直覺：「開啟原工程資料夾」或拖入資料夾，一次載入骨架、角色圖片或圖集；「點角色加效果」在角色圖片上點一下，就設好骨骼、位置、開始時間與前後圖層；時間軸可拖曳粒子段落並吸附事件與關鍵幀；「寫回原工程」直接覆寫原 JSON 並放入新圖片，寫入前自動備份到 `_particle_backup/`，重開資料夾會自動替換上次的粒子。

## v1.26 重點

多圖隨機粒子：「載入隨機圖」一次選多張圖片，每顆粒子出生時隨機挑一張、整個生命不換圖；與依序播放的連續圖分開。

「RESET／新專案」可從初始設定開始製作另一個效果，提供「儲存後新建」與「直接新建」。新專案會立即保存為本機草稿；已存專案檔與「我的效果」會保留。

## v1.25 重點

輸出時自動烘焙、拖放載入、完整快捷鍵、游標縮放到 800%、圖層單獨顯示／預覽隱藏、每層開始時間與「圖層時間」拖曳、內建效果與我的效果合併、批次輸出多版本與配色變體、參數區塊可收合。未設定開始時間的舊專案，烘焙與輸出結果與 v1.24 完全相同。

## 開發

可編輯來源是根目錄的 `index.html`、`styles.css` 和各 JavaScript 檔。v1.27 新增 `spine-folder.js`（資料夾載入與寫回）、`art-picker.js`（點選角色圖片）、`attach-assist.js`（時間吸附與圖層計算）；v1.28 新增 `lightning.js`（網格閃電的生成、取樣與輸出）；v1.29 新增 `trail.js`（沿路徑拉伸與殘影拖尾）。安裝 Node.js 後：

- `node scripts/build.js`：重新產生單檔離線版 `dist/Particle-Studio.html`
- `npm test`：執行單元測試
- `node scripts/build-release.js`：產生並驗證下載包 `dist/Particle-Studio-v<版本>.zip`

舊版下載包移到 `_封存/舊版發佈包/`；測試、分析與交付草稿不包含在下載包內。

## 技術備註

烘焙品質 `fine`、`standard`、`compact` 是選填專案欄位；未設定的舊專案保留既有輸出。品質只調整匯出曲線精簡與補採樣門檻，不改取樣模擬、亂數或生命週期。`ParticleCore.estimateCost` 使用有界的粒子池資料估算補採樣前的成本，實際 KEY 數與 JSON bytes 由試烘焙後的輸出取得。新品質設定匯出適用 2,000,000 取樣限制；估算上限本身不直接拒絕烘焙。

介面設計以日常編輯的便利與直覺性為優先：保留常用控制項的順序，新增功能按需啟用，較少用的選項預設收合。切換模式會保留原值，停用欄位須在所在分頁解釋原因；拖曳紅點或數值不重設捲動位置。新增功能不應要求使用者先理解烘焙的實作細節才能操作。
